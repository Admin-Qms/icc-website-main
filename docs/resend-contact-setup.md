| Variable | Value |

| `RESEND_API_KEY` | A Resend sending-only key restricted to `isocertificationconsultants.ca`; never put the token in Git or a `NEXT_PUBLIC_` variable |

`anthony.mannella@isocertificationconsultants.ca`. Replies go to the visitor's

## Final activation

1. Verify the domain in Resend.
2. Confirm the two server-only Vercel settings are saved for the deployment environment.
3. Deploy the branch through the project's normal Git deployment process.
4. Submit one clearly labelled test enquiry from the deployed contact page.
5. Confirm both the success message and Resend's delivery event. A delivery event
   means the recipient's mail server accepted the email; inbox placement still
   needs an inbox check.

The endpoint validates fields and request sizes, rejects cross-origin browser
submissions, uses a honeypot, and limits each client to five attempts per ten
minutes per running function instance. This limit is best effort across Vercel
instances; use Vercel Firewall if a shared deployment-wide limit is needed.
Identical enquiry retries reuse one Resend idempotency key for 24 hours.
Operational logs contain provider status/email ID, never enquiry text or keys.
